ОБУЧЕНИЕ — Ограниченные источники и кандидаты на проверку
==========================================================

НАЗНАЧЕНИЕ
----------
Learning проверяет явно разрешённый источник вместе с предложением по обучению, переданным вызывающей стороной. Проверяются происхождение, хеши, формат, сигналы выбора, приватность и возможные дубликаты. Сервис сам не выбирает опыт и не доказывает повторное использование или качество результата.

СПИСОК РАЗРЕШЁННЫХ ИСТОЧНИКОВ
-----------------------------
BACH_LEARNING_SOURCE_ROOTS — JSON-объект, сопоставляющий идентификаторы корней существующим абсолютным каталогам. По умолчанию задано {}; источники не разрешены. Запрос указывает только идентификатор корня и относительный путь. Пути с .., корни-символические ссылки и выходы за разрешённый корень отклоняются. Для каждого источника обязателен явный хеш SHA-256.

ПОДДЕРЖИВАЕМЫЕ ИСТОЧНИКИ
------------------------
- session: подготовленный JSON-экспорт со схемой bach.learning-source.v1, session_id и не более чем 200 уникальными событиями. Допустимые роли: user, assistant или tool; поля tool и outcome необязательны. Для кандидата хотя бы одно выбранное событие user должно содержать распознанный маркер выбора. Иначе результат — no_candidate.
- hermes_ledger: нативный Hermes JSONL-журнал с уникальным 12-значным шестнадцатеричным entry_id в нижнем регистре. Событие обслуживания create, edit, update или patch должно содержать манифест after с путями и хешами SHA-256. Все файлы должны находиться в разрешённом корне. Журнал — телеметрия, а не одобрение или доказательство качества; адаптер читает формат и не запускает Hermes curator.
- nemofold_voyage: исходный файл из нативной библиотеки run-reports/web-console/voyages. NemoFold VoyageStore.load вызывается с require_receipt=True. Проверяются receipt, контракт задания, хеш файла и voyage ID. Это подтверждает сохранённый план, но не его выполнение.

ОГРАНИЧЕНИЯ И ПРИВАТНОСТЬ
-------------------------
Размер источника не превышает 1 000 000 байт; манифест Hermes вместе со связанными файлами подчиняется тому же общему пределу, а каждый связанный файл ограничен 200 000 байт. Размер receipt ограничен 4 096 байт. Размер запроса не превышает 200 000 байт. Эти пределы источников не являются общим лимитом на все отдельные чтения каталога и руководств.

Сервис отклоняет обнаруженные шаблоны путей, учётных записей, IP-адресов и учётных данных, а также поля с учётными данными. Фильтр шаблонов не является полным семантическим детектором секретов. Частные литералы можно заменить параметром с именем, значением и описанием; в предложении вместо них используется маркер <NAME>. Имена, похожие на учётные данные, также запрещены в качестве ключей словаря.

Локаторы источников и событий остаются внутренними метаданными происхождения в контракте кандидата. Для списков и подробных записей кандидатов требуется активный токен устройства; эти локаторы не входят в публикуемый контент skill или цепочки.

АНАЛИЗ, ХРАНЕНИЕ И ПРОВЕРКА
---------------------------
Полное предложение содержит kind (skill, chain или rule), name, trigger, reason, body, event_ids, parameters, side_effects, required_capabilities и dedup. Сервис читает существующие соседние элементы из разрешённых каталогов навыков и цепочек и связывает переданное вызывающей стороной решение о дедупликации и, если применимо, базовую версию; самостоятельное семантическое решение о дубликате он не принимает. Выбор и решение о дедупликации по-прежнему требуют проверки. В контракте отмечаются semantic_review_required=true и empirically_validated=false.

CLI:
  bach learning analyze <request.json>
  bach learning store <request.json> --dry-run
  bach learning store <request.json> -n
  bach learning store <request.json>

analyze всегда работает только на чтение. store с --dry-run или -n показывает предварительный результат без сохранения. store без этих флагов сохраняет только неактивного версионируемого кандидата в существующее хранилище проверки Hermes или NemoFold. Для обновления вместе обязательны expected_revision и expected_digest. Повтор идентичного содержимого распознаётся идемпотентно; конфликты версий отклоняются.

HTTP:
  POST /api/learning/sources/analyze
  POST /api/learning/sources/store

Обе конечные точки сначала требуют действительный активный токен устройства, переданный в заголовке Authorization: Bearer или cookie bach_device_token. Затем они используют тот же конвейер обработчика. analyze остаётся операцией чтения. store ничего не публикует и не активирует.

PYTHON API
----------
  from bach_api import learning
  learning.analyze("request.json")
  learning.store("request.json")

Упрощённые вызовы при успехе возвращают результат JSON как текст, а не как Python-словарь. При ошибке прокси выводит сообщение об ошибке и возвращает его текстом; не передавайте текст ошибки в json.loads. Для совместимого формата возврата:
  success, message = learning.raw("analyze", "request.json")
success — bool; message содержит JSON-текст при успехе и обычный текст ошибки при неудаче.

ГРАНИЦЫ ПРОВЕРКИ
----------------
Кандидат на проверку не является одобренной skill. Адаптер не создаёт активный файл skill, не выдаёт инструменты или возможности и не настраивает scheduler. Правила — проекты без полномочий управления; для scheduler требуется отдельное разрешение. Карантин и проверка из зависимости PR 303 продолжают действовать.

Руководства skill-extractor и workflow-extract действительно читаются; фиксируются разрешённая версия и хеш. Руководства не исполняются. Версия не закреплена на 1.3.1, поскольку при разрешении каталога во время выполнения может быть выбрана другая. Файлы фиксированно поддерживаемых справочных материалов neutralisierung.md, transcript-quellen.md и automation-bausteine.md читаются и хешируются, если они упомянуты в руководствах; они не исполняются.

Существующие прямые пути Hermes distill и NemoFold synthesize вместе со своими эвристиками сохраняются. Они не реализуют общий контракт и не являются нативной интеграцией исходных форматов. Успех кода или CI не доказывает установку или запуск на Mac Studio. Нативное повышение, независимое повторное использование с подтверждением качества, фиксация провайдера, автоматический экспорт сессий и планировщик остаются отдельными незавершёнными задачами.
