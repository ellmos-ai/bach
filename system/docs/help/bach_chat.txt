BACH CHAT SERVICE - Multi-Backend Telegram Bot + Control API + Web-GUI + Tray
=============================================================================

BESCHREIBUNG
------------
BACH Chat Service ist der Nachfolger der Claude Bridge. Er bietet einen
BACH-integrierten Telegram-Bot mit pluggbaren LLM-Backends, einer
HTTP Control API, Web-GUI und einem cross-platform System Tray.

Architektur (4 Schichten):
  - model_backend.py:   Pluggbare Backend-Abstraktion (Ollama, Claude CLI,
                         Codex CLI, Claude API, OpenAI API)
  - session_store.py:   Kanonische Persistenz & Transkripte in bach.db
                         (Tabelle session_snapshots, Typ chat-transcript.v1)
  - chat_runtime.py:    Backend-unabhängige Chat-Runtime mit Tool-Use-Loop,
                         Kontextmanagement, 24h-Auto-Reset, Forking, Zusammenfassung
  - telegram_chat.py:   Telegram-Bot mit allen Befehlen + Control API (Port 8081)
  - gui/server.py:      FastAPI Web-Server mit Chat-Proxy & Transkript-Board (:8000/chat)
  - chat_tray.py:       Cross-platform System Tray (macOS/Windows/Linux)

Backends:
  - ollama:     Lokaler Ollama-Server mit nativem Tool-Use
  - lmstudio:   LM Studio (lokal via OpenAI-kompatibles API, Port 1234, Auto-Modellerkennung)
  - hermes:     Nous Hermes Agent (OpenRouter / Lokal via OpenAI-kompatibles API)
  - claude:     Claude Code CLI (--continue Session, eigene Tools)
  - codex:      Codex CLI (GPT-Modelle, eigene Tools)
  - claude-api: Anthropic API (benötigt ANTHROPIC_API_KEY)
  - openai:     OpenAI API (benötigt OPENAI_API_KEY)

Sicherheitsmodi:
  - safe:  Nur lesende Tools (ls, cat, grep, git, docker, etc.)
  - full:  Auch schreibende Tools (execute_command, write_file)
           Aktivierung: /mode full bestätigt

SESSION-LIFECYCLE & ARCHIVIERUNG
---------------------------------
Jeder Transportkanal besitzt einen eigenen Session-Kontext:
  - Web-GUI:            chat_id = "gui-web"
  - Telegram:           chat_id = "<numeric_telegram_chat_id>"
  - Background-Worker:  chat_id = "idle-worker"
  - Tray:               chat_id = "tray-prompt"

Lifecycle-Regeln:
  1. 24h-Inaktivitäts-Reset: War eine Session länger als 24 Stunden inaktiv
     (TTL 86400s), wird sie beim nächsten Zugriff automatisch archiviert
     und mit einem leeren Verlauf frisch gestartet.
  2. Manueller Reset:
     - Telegram: /clear archiviert die Konversation und leert den Speicher.
     - Web-GUI:  Button [ ➕ Neuer Chat ] archiviert und setzt die Ansicht zurück.
  3. Zero-Data-Loss: Kein Chat geht verloren. Vor jedem Reset (ob 24h Timeout,
     manueller Clear oder vor einem Fork) wird der Zustand in bach.db unter
     session_snapshots als permanenter Archiv-Snapshot abgelegt.
  4. Protokolle & Forking:
     - Im Web-Chat (:8000/chat) öffnet [ 📜 Protokolle ] das Transkript-Board.
     - Frühere Sessions (Web, Telegram, Worker) können eingesehen und über
       [ 🔄 Im Web-Chat fortsetzen (Fork) ] in den Web-Chat übernommen werden.


TELEGRAM BEFEHLE
-----------------
  /start                    Willkommensnachricht
  /clear                    Konversation archivieren und neue Session starten
  /backend [name] [model]   Backend wechseln (ollama|lmstudio|hermes|claude|codex|claude-api|openai)
  /model <name>             Modell wechseln
  /mode [safe|full]         Sicherheitsmodus
  /think                    Denkmodus AN (gründlich)
  /nothink                  Denkmodus AUS (schnell)
  /settings                 Alle Einstellungen anzeigen
  /status                   System-Status
  /remember <text>          BACH Memory: Merken
  /recall <suche>           BACH Memory: Suchen
  /facts                    BACH Memory: Fakten
  /bach <cmd>               BACH-Befehl ausführen
  /task <text>              Task anlegen
  /tasks                    Offene Tasks
  /maxrounds [N]            Max Tool-Runden setzen (0=unbegrenzt)
  Sprachnachricht           Whisper-Transkription -> Chat
  Foto                      OCR-Texterkennung -> Chat


CONTROL API (Port 8081 / Proxied via :8000/api/chat-control)
------------------------------------------------------------
  GET  /                    Web-Dashboard (HTML)
  GET  /api/status          Aktueller Status (inkl. Tool-Aktivität)
  GET  /api/backends        Verfügbare Backends mit Status
  GET  /api/models          Modelle des aktuellen Backends
  GET  /api/history         Sichtbarer Verlauf: ?chat_id=gui-web
  GET  /api/sessions        Transkript-Snapshots: ?limit=50
  GET  /api/session         Einzelnes Transkript per ID: ?id=123
  POST /api/backend         Backend wechseln: {"name": "claude", "model": "opus"}
  POST /api/mode            Modus setzen: {"mode": "safe"}
  POST /api/model           Modell setzen: {"model": "qwen3.5:35b-a3b"}
  POST /api/think           Denkmodus: {"think": true}
  POST /api/max_tool_rounds Max Tool-Runden: {"rounds": 10} (0=unbegrenzt)
  POST /api/chat            Chat-Nachricht: {"prompt": "...", "chat_id": "..."}
  POST /api/clear           Session archivieren & leeren: {"chat_id": "gui-web"}
  POST /api/fork            Snapshot wiederbeleben: {"chat_id": "gui-web", "snapshot_id": 123}


SYSTEM TRAY
-----------
  Start:  python start/startspine.py start --tray

  Funktionen:
    - Status-Icon: Grün (safe), Orange (full), Rot (nicht verbunden)
    - Backend-Submenu: Alle Backends mit Verfügbarkeit
    - Modell-Untermenü: Modelle des aktuellen Backends
    - Modus-Toggle: Safe/Full
    - Think-Toggle: AN/AUS
    - Max Tool-Runden: Presets (5/10/20/Unbegrenzt)
    - Tool-Aktivität: Aktuelles Tool + Runde im Tray-Titel
    - Web-Dashboard öffnen
    - Cross-platform: macOS, Windows, Linux (via pystray)

  Remote-Tray (nur über eine separat abgesicherte Netzwerkstrecke):
    python start/startspine.py start --tray --host bach-server.local

  Sicherheitsgrenze: Remotezugriff benötigt eine ausdrückliche
  Authentifizierungsentscheidung. Die Control-API darf nicht ungeschützt
  auf 0.0.0.0 veröffentlicht werden.

KONFIGURATION
-------------
  ~/.config/bach/telegram_chat.json:
    {
      "bot_token": "...",
      "owner_id": "...",
      "backend": {
        "type": "ollama",
        "base_url": "http://localhost:11434",
        "default_model": "qwen3.5:35b-a3b"
      }
    }

  Umgebungsvariablen:
    TELEGRAM_BOT_TOKEN       Bot-Token (Alternative zu Datei)
    TELEGRAM_OWNER_ID        Chat-ID des Owners
    OLLAMA_MODEL             Standard-Modell überschreiben
    OLLAMA_URL               Ollama-URL überschreiben
    LM_STUDIO_URL            LM Studio URL (default: http://localhost:1234/v1)
    LM_STUDIO_MODEL          LM Studio Modell überschreiben (default: auto)
    BACH_CONTROL_PORT        Control API Port (default: 8081)
    BACH_HOST                Default-Host für Tray/GUI (z. B. bach-server.local)
    BACH_NO_BROWSER          =1: Browser nicht automatisch öffnen (Remote-GUI)
    ANTHROPIC_API_KEY        Für claude-api Backend
    OPENAI_API_KEY           Für openai Backend


HINWEISE
--------
  Threading: Die Control API nutzt ThreadingHTTPServer (ab v1.1.1).
  ChatRuntime hat keine Locks um shared State (sessions, current_tool,
  tool_round, last_tools). Bei Single-User-Betrieb unkritisch, aber bei
  gleichzeitigen API-Anfragen während laufender Tool-Ausführung kann
  es zu Race Conditions kommen. Workaround: Nur einen Chat gleichzeitig.


MIGRATION VON CLAUDE BRIDGE
----------------------------
  Der BACH Chat Service ersetzt die Claude Bridge funktional:
  - bridge_daemon.py -> telegram_chat.py (Telegram-Bot)
  - bridge_tray.py   -> chat_tray.py (System Tray)
  - config.json      -> ~/.config/bach/telegram_chat.json

  Vorteile gegenüber Claude Bridge:
  - 5 Backends statt nur Claude CLI
  - BACH-Integration (Memory, Tasks, Injektoren)
  - Control API + Web-Dashboard
  - Voice (Whisper) + OCR (Tesseract)
  - Cross-platform Tray
  - Saubere 3-Schichten-Architektur
