# SECRETS

BACH speichert Secret-Werte ausschließlich im Schlüsselbund des Betriebssystems
(unter Windows im Credential Manager). `bach.db` und
`~/.bach/bach_secrets.json` enthalten nur Key, Beschreibung, Kategorie und den
Backend-Marker. Ein fehlender Metadatenindex löscht keine Credentials.

Operationen
-----------

`bach secrets list`
    Listet ausschließlich Metadaten und den Backend-Status.

`bach secrets get <key>`
    Prüft die Verfügbarkeit. Der Secret-Wert wird nie auf stdout ausgegeben.

`bach secrets set <key> [--desc=TEXT] [--category=CAT]`
    Fragt den Wert verdeckt interaktiv ab. Ein Wert als Prozessargument wird
    abgewiesen.

`bach secrets set <key> --stdin [--desc=TEXT] [--category=CAT]`
    Liest den Wert für Automationen aus stdin. BACH protokolliert ihn nicht.

`bach secrets delete <key>`
    Löscht Wert und Metadaten.

`bach secrets sync`
    Migriert vorhandene Legacy-Klartextwerte erst nach verifiziertem Schreiben
    in den OS-Schlüsselbund. Konflikte brechen die Migration ohne Bereinigung
    der Klartextquelle ab.

Sicherheit
----------

- Keine Secret-Werte in CLI-Argumenten, stdout, SQLite oder JSON.
- Die Migration prüft jeden Keyring-Eintrag durch unmittelbares Zurücklesen.
- JSON wird atomar ersetzt; SQLite-Freelist und WAL werden anschließend nach
  Möglichkeit bereinigt.
- `_secret_refs` in Connector-Konfigurationen werden erst zur Laufzeit über den
  zentralen Keyring-Resolver aufgelöst.

Dateien
-------

- `hub/secrets_handler.py`: Keyring-Resolver, Migration und CLI.
- `bach.db:secrets`: Metadatenindex mit `keyring://ellmos-bach` als Wertmarker.
- `~/.bach/bach_secrets.json`: portabler Metadatenindex ohne Secret-Werte.
