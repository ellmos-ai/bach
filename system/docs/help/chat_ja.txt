BUDDHA CHAT & セッションプロトコル
==================

説明
--
Buddha Chat は BACH の対話型アシスタントインターフェースであり、Web-GUI
(http://localhost:8000/chat) および Telegram ボット経由で利用できます。Buddha は
質問への回答、作業の計画、BACH ツールの実行を行い、bach.db 内の正規スナップ
ショットを通じてコンテキストを管理します。

アクセス経路
------
1. Web-Chat:     http://localhost:8000/chat
                 固定セッション ID "gui-web" を使用します。ページを再読み込み
                 してもメッセージは保持されます (自動復元)。
2. Telegram ボット: @BachBuddhaBot (または設定されたトークン)
                 各 Telegram チャットは固有の数値チャット ID を持ちます。
3. システムトレイ: モデル/モード選択とクイックアクセスを備えたステータスバー。

セッションライフサイクル & 自動リセット
-------------------
古く完了済みのトピックが思考コンテキストに恒久的に残るのを防ぐため、各チャット
セッションには以下のライフサイクルが適用されます:
1. 24 時間非アクティブ時のリセット (TTL):
- チャットが 24 時間以上使用されなかった場合 (last_active > 86400s)、次のメッ
  セージ受信時に自動的にアーカイブされ、空の状態にリセットされます。
- ユーザーは翌日、自動的にフレッシュな状態で開始できます。

2. 手動リセット:
- Telegram:  コマンド /clear
- Web-GUI:   ステータスバーのボタン [ ➕ Neuer Chat ]
- どちらの方法も、クリアする前にこれまでの履歴を完全にアーカイブします。

3. Zero-Data-Loss 保証:
- メッセージ履歴が回復不能な形で削除されることはありません。
- すべてのセッションは、中央 bach.db の session_snapshots テーブルに永続的な
  トランスクリプト (タイプ: chat-transcript.v1) として保存されます。

プロトコル & フォーク (再開)
--------------
Web-GUI (http://localhost:8000/chat) にはボタン [ 📉 Protokolle ] があります:
1. アーカイブ概要:
- Web、Telegram、および Worker から記録されたすべてのセッションを時系列で表示
  します。
- "Alle"、"Web"、"Telegram"、"Archiv" でフィルタリング可能です。

2. トランスクリプト検査:
- エントリをクリックすると、タイムスタンプとフォーマット付きのすべてのユーザーお
  よびアシスタントメッセージを含む完全なトランスクリプトが開きます。

3. Web-Chat で続行 (Fork):
- ボタン [ 🔑 Im Web-Chat fortsetzen (Fork) ] を使うと、任意の過去のセッション
  (Telegram または以前の Web セッション) を現在の Web-Chat に読み込み、そのまま
  議論を続けることができます。
- 既存の Web セッションは事前に自動的にバックアップされます。

セキュリティモード
---------
  - safe:  読み取り専用のクエリのみ (ls, cat, grep, git status など)。
  - full:  書き込みツールも許可 (ファイル作成、コマンド実行)。
           Telegram の場合: /mode full で確認
           Web-GUI の場合:  Control-Dashboard / API 経由
