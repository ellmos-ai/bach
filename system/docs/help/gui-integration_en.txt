Shared GUI, Agents, and Ocean Transfer
======================================

The UI source resides in ellmos-system-gui. BACH consumes a verified release
archive; system/gui/kit_manifest.json pins source commit and archive hash.

The three cards for creation, ready-made agents, and ready-made teams form a
shared group with blue accents. In light mode their surfaces are white;
the two Living sections remain collapsed when first opened.

The former URLs /agents-board and /skills-board are redirects.
Fabrika leads to the consolidated blueprint editor.

INSPECTION
GET /api/gui/backend-origin   Actual backend and instance binding
GET /api/gui/capabilities     Registered adapters and open acceptances
GET /api/gui/kit-manifest     GUI pin and installed file check
GET /api/task-assignees       Actual assignment targets and configuration version

A registered adapter is not proof of a productive run.
Living means available; Running requires an observed run.
The model name alone does not confirm successful inference.
A locally started worker shares actual compute ownership.
Cloud workers are started explicitly.
The enabled fixed Always-On worker can be resumed on the lead after a control
start with a proven local model. Manual pause and stop are preserved; see
always-on-startup.txt. This local resumption is not a cloud autostart.

ASSIGNMENT
Native assignments use assigned_slot, assigned_to, and required_model.
Changes including releasing a previous native assignment require the current
assignment_configuration_version. A conflict requires re-reading; there is no
silent retry or automatic start.

Dynamic worker profiles are also typed assignment targets. Their stored
provider, model, and authenticated status proof must match. Paused, failed,
expired, or private relay profiles cannot be selected.
Assign task in Living/Running opens the task form with the profile; saving
binds the task to its actual ID. The global configuration version is checked
after the status fetch and immediately before the task commit.
An assignment does not start a worker and does not acquire a task lease.

GOVERNANCE
BACH_POLICY_REGISTRY_ENABLED=1 enables the optional canonical reader.
The registry is found by the provider via POLICY_REGISTRY_PATH or its own
default. Missing registry or wrong provenance results in an error.
Read: /api/governance/policy-registry and /api/governance/effective-policy.
The DecisionClicker write path is a separately enabled capability.
