WORKER-SCOPE-EVIDENCE — Доказательства проекта и worktree для результатов
=========================================================================

Отправленный результат может получить неизменяемое доказательство области
(Scope). Первый адаптер использует существующую регистрацию чистого
рабочего дерева задачи BACH на bach-task/<Task-ID>. Другим проектам
требуется собственное подключение к их фактическому авторитету
репозитория/области. Отсутствие доказательств не препятствует прежней
личной приёмке или доработке.

Приватный контроллер фиксирует канонический Result, его версию задачи,
поколение, fence и ревизию сдачи, а также репозиторий, ветку, Head и дерево
Git. Разрешённые локальные пути сохраняются только как SHA-256. Имеющийся
публичный пин источника проверяется; его отсутствие не выдаётся за публично
подтверждённое происхождение. Промпты, ответы, приватные Lease-ID и учётные
данные не входят в это доказательство.

Определённая область Git охватывает индекс, отслеживаемые файлы и
неигнорируемые новые файлы. Изменения staged/unstaged/untracked, а также
assume-unchanged и skip-worktree препятствуют положительному доказательству.
Подмодули и настроенные файловые фильтры Git остаются недоступными в первом
адаптере; эта проверка области не запускает программы фильтрации.
Игнорируемые файлы явно находятся вне этой области Git. Чистый коммит не
доказывает содержательное выполнение задания.

Git и SQLite не имеют общей транзакции. Git и текущие блокировки
фиксируются вне блокировки записи SQLite; внутри блокировки записи
каноническая привязка результата проверяется повторно. Доказательство
описывает наблюдаемое состояние. Оно не доказывает постоянную
эксклюзивность или неизменность между двумя запросами.

read_result() проверяет внутри снимка чтения SQLite исключительно
сохранённые доказательства и историю. result.scope.availability=recorded
означает: историческое доказательство действительно, текущий worktree ещё
не подтверждён повторно. result.result_revision при этом остаётся null.
Локальный запрос SDK и API-GET затем повторно проверяют
Git/регистрацию/блокировки. API выполняет эту проверку после закрытия
соединения вне своего цикла событий. Уже открытый вызывающей стороной
снимок SQLite не закрывается SDK; внутри этого снимка дополнительная
проекция Git не выполняется.

Только при неизменно подтверждённой области появляется
availability=available. Изменившийся Head, грязное дерево или недоступный
сервис Git/блокировок возвращает unavailable и не даёт полной ревизии
результата. Существующее доказательство результата никогда не
перезаписывается более новым состоянием worktree. Новая отправка требует
нового поколения результата.

Полная result_revision связывает ревизию сдачи, фактически подтверждённую
ревизию выполнения и дайджест/событие истории доказательства области. При
отсутствии доказательства выполнения она остаётся null. При запусках CLI
область может присутствовать уже после Submit; тем не менее ревизия
возникает только после фактического возврата модели и подтверждённой связки
выполнения. Потерянные Submit-ACK могут быть реконструированы только через
точное каноническое чтение собственной приватной ожидаемой сдачи.

Приватный локальный захват использует TaskLeaseClient._capture_task_scope и
WorkerLeaseBinding.capture_confirmed_scope. Диспетчер вызывает их после
подтверждённой операции задачи вне блокировки привязки. Прямые локальные
вызывающие стороны могут вызывать их явно; result_state при необходимости
сначала реконструирует фактический Submit. Повторный успешный захват того
же ID результата предотвращается в Binding. Текущие публичные запросы
продолжают повторно проверять свою область. Удалённые клиенты не получают ни
эндпоинта самодекларации, ни локального DB-fallback.

Действительная ревизия не даёт ни прав рецензирования, ни Done. Идентичность
автора и рецензента, уровень модели, независимость, содержательный контракт
задачи, обязанность пользователя и шлюзы GitHub должны предоставлять свои
собственные авторизованные доказательства. Последующее одобрение должно
повторно проверять актуальное на тот момент состояние.
