# SECRETS

BACH stores secret values exclusively in the operating-system keyring (Windows
Credential Manager on Windows). `bach.db` and `~/.bach/bach_secrets.json`
contain only the key, description, category, and backend marker. A missing
metadata index never deletes credentials.

Operations
----------

`bach secrets list`
    Lists metadata and backend status only.

`bach secrets get <key>`
    Checks availability. The secret value is never written to stdout.

`bach secrets set <key> [--desc=TEXT] [--category=CAT]`
    Prompts for a hidden interactive value. Values passed as process arguments
    are rejected.

`bach secrets set <key> --stdin [--desc=TEXT] [--category=CAT]`
    Reads an automation value from stdin without logging it.

`bach secrets delete <key>`
    Deletes the value and its metadata.

`bach secrets sync`
    Migrates legacy plaintext only after each keyring write has been verified.
    A conflict aborts without scrubbing the plaintext source.

Security
--------

- No secret values in CLI arguments, stdout, SQLite, or JSON.
- Migration verifies each keyring entry by reading it back immediately.
- JSON replacement is atomic; SQLite freelist and WAL are cleaned afterwards
  where supported.
- Connector `_secret_refs` resolve through the central keyring resolver at run
  time.

Files
-----

- `hub/secrets_handler.py`: keyring resolver, migration, and CLI.
- `bach.db:secrets`: metadata index using `keyring://ellmos-bach` as marker.
- `~/.bach/bach_secrets.json`: portable metadata index without secret values.
