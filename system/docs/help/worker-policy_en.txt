WORKER POLICY: CONFIGURATION AND LEASE DISPLAY
============================================

PREREQUISITE
The shared task master contract taskplan.worker_policy must be installed:
worker-review-policy.v1alpha1. If it is missing or its version is unknown,
worker policy rules are unavailable. There is no second BACH policy fallback.

Explicitly install the optional package from the BACH root:
python -m pip install -e ".[worker-policy]"

The extra pins the shared core to the validated task master commit
5924b71b2a93e59e625b5c9afaa6e84966bf49d3. The generic version number
taskplan==0.7.0 alone does not identify this state. This installation path
is separate from the old setup.py --extras. After installation, read
status independently. An installation starts no worker and replaces no user
acceptance.

ENTRY POINTS VIA CLI AND LIBRARY
bach worker-policy status
bach worker-policy task_show 41

from bach_api import worker_policy
ok, text = worker_policy.raw("status")
ok, text = worker_policy.raw("task_show", 41)

set accepts a JSON object with configuration_version, policy and selection.
task_set accepts the task ID and JSON with task_id, task_version,
configuration_version and override. Example without any write action:

import json
ok, text = worker_policy.raw("status")
snapshot = json.loads(text) if ok else None

Always read the version values fresh; in case of conflict, reload and reconcile
changes deliberately. A rejected mutation is not automatically repeated.

GUI API
GET/PUT /api/system/worker-policy
GET/PUT /api/tasks/{id}/worker-policy

All four accesses require an active registered device. Tokens belong
in the existing Authorization header or the device cookie, not in URLs.
Local/native library use relies on the same configuration service.

RULES AND STORAGE
The global policy and task-bound overrides live in the existing
system_config store of the canonical BACH database. Revision and CAS are
separated from task content and status. A reset increments the configuration
revision; even switching back to identical values invalidates older write
states. Reads change neither schema nor configuration. A missing store is not
equivalent to an empty, valid default.

mode=null inherits the mode. Boolean overrides distinguish null, false and
true. A set user review obligation cannot be removed by false or by a reset.
Stored rules confer no review authority.

A storage confirmation starts no worker and accepts no result. The task view
explicitly reports not_evaluated without validated result integrity. The result
service, selection and actual execution must apply the rules separately. This
configuration projection is neither a production nor a user acceptance.

LEASE DISPLAY
The existing worker/core agent status paths can project an active task lease
from a confirmed controller and canonical task binding. Generation, task
version, holder, fence, heartbeat and expiry must agree. A stored task ID or
profile status alone does not prove an active lease.

lease_id in this status projection is a public observation reference
sha256:<digest>, identified by lease_id_kind=observation_sha256 and
source=native_task_db. The private claim ID stays with the lease client. The
observation reference grants no claim, renew or release right.

The countdown and sorting are optional display. They change neither the task
lease nor the turn budget, extend no runtime and start no work.
