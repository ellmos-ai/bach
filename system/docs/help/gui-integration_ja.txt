共通 GUI、エージェント、および Ocean 転送
=====================

UI ソースは ellmos-system-gui にあります。BACH は検証済みのリリースアーカイブ
を使用します。system/gui/kit_manifest.json がソースコミットとアーカイブハッシュ
を固定します。

ビュー
/agenten/running       Living スロットと実際に観測された実行
/agenten/blueprints    テンプレート、ロール、およびブループリントインスタンス
/agenten/marblerun     ネイティブエージェントチェーンと順序付きスキルチェーン
/tasks                 タスクおよび利用可能な型付き割り当て先
/skills                現在のスキルソースとバージョン履歴
/skills/plugins        プラグインボード
/skills/mcp            MCP ボード
/skills/software       ソフトウェアボード

作成、完成済みエージェント、完成済みチームの 3 つのカードは、青いアクセントを持つ
共通グループを形成します。ライトモードでは背景面が白くなり、2 つの Living エリア
は初回表示時に折りたたまれたままになります。

以前の URL /agents-board および /skills-board はリダイレクトです。
Fabrika は統合されたブループリントエディタへ案内します。

ポートレート選択
70 枚の画像: 初期のポートレート 6 枚、従来の Gemini 画像 19 枚、新しい 10 枚シ
リーズ 3 種 (コミックエージェント、Gemini ロール、かわいいワークショップロボッ
ト)、さらにモンスター 10 体とスライムボール 5 個。この選択はエージェントワーク
ショップおよびエージェント設定ダイアログで利用できます。追加画像は既存の画像契
約内で 256 ピクセルの PNG を使用します。画像コンテンツが保存されるため、バック
エンドの新しいプリセット ID は不要です。出所とソースハッシュは共通 GUI リポジト
リの src/assets/agent-portraits-20261010/provenance.json にあります。

検証
GET /api/gui/backend-origin   実際のバックエンドとインスタンスバインディング
GET /api/gui/capabilities     登録済みアダプタと未完了の受け入れ
GET /api/gui/kit-manifest     GUI ピンとインストール済みファイルチェック
GET /api/task-assignees       実際の割り当て先と設定バージョン

登録済みアダプタは本番実行の証明ではありません。
Living は利用可能を意味し、Running には観測された実行が必要です。
モデル名だけでは推論の成功を確認できません。
ローカルで起動されたワーカーは実際のコンピュート所有権を共有します。
クラウドワーカーは明示的に起動されます。
有効化された固定 Always-On ワーカーは、ローカルモデルが証明された Control 起動
後にリード上で再開できます。手動の一時停止と停止は保持されます。
always-on-startup.txt を参照してください。このローカル再開はクラウドの自動起
動ではありません。

割り当て
ネイティブ割り当てでは assigned_slot、assigned_to、required_model を使用します。
以前のネイティブ割り当ての解除を含む変更には、現在の
assignment_configuration_version が必要です。競合が発生した場合は再読み込みが
必要であり、サイレントな再試行や自動起動は行われません。

動的ワーカープロファイルも型付き割り当て先です。保存されたプロバイダ、モデル、お
よび認証済みステータス証明が一致している必要があります。一時停止中、エラー状態、
期限切れ、またはプライベートのチェーンプロファイルは選択できません。Living/
Running でタスクを割り当てると、そのプロファイルでタスクフォームが開き、保存す
るとタスクが実際の ID にバインドされます。グローバル設定バージョンはステータス取
得後かつタスクコミット直前にチェックされます。割り当てはワーカーを起動せず、タス
クリースも取得しません。

ガバナンス
BACH_POLICY_REGISTRY_ENABLED=1 によりオプションの正規リーダーが有効になります。
レジストリはプロバイダによって POLICY_REGISTRY_PATH または独自のデフォルトから
検出されます。レジストリが欠落しているか出所が誤っている場合はエラーになります。
読み取り: /api/governance/policy-registry および
/api/governance/effective-policy。DecisionClicker 書き込みパスは別途有効化が
必要な機能です。
