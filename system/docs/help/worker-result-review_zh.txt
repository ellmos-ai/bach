模型独立审查结果
========

提交的 Worker 结果最初保持在 review 状态。模型审查是同一任务数据库和队列中
的一个额外任务。匹配的普通任务会优先被接管。不存在额外的调度器，也不存在自动
模型供给。

前提条件
----
本地控制器需要一条已确认的 HTTP 后端路由、一次实际的模型返回、一次有效的结
果提交以及一份当前的 Git 工作副本证明。单独授权的人员在现有 Worker 设置中将
模型别名映射到模型身份，并确定允许的审查者及其级别。仅凭一般设备注册不足以获
得这些权限。更改使用现有的配置版本，并在并行更改时被拒绝。

计划的模型名称或槽位标签不能证明身份。实际路由以及调用期间有效的别名映射会记
录在执行证明中。旧证明不会在事后获得模型身份。缺失或被修改的证明不允许进行独
立审查。API 密钥保留在进程中，既不以文本形式也不以密钥哈希形式出现在这些证
明中。

流程
--
在有效提交后，如果启用了审查接管，则会针对具体的完整结果修订版本精确创建一个
审查任务。目标任务保持 review 状态。审查任务不依赖于目标任务的 Done。控制器
会为另一个模型身份、另一个槽位和另一个运行代际授予一个私有且不可转让的
Grant。公开或外部声明不会因此获得额外权限。

审查会通过现有的模型、资源、租约和停止检查。它可以读取目标委托和结果，并且只
能提交自己的审查结果。控制器将实际的最后一次模型返回精确绑定到此 Submit 调
用。模型关于身份或独立性的声明不会被采纳为授权。

结构化裁决包含 status（approved、findings 或 rejected）、summary 和
task_contract_met。approved 需要 task_contract_met=true。缺失的审查证明必
须作为发现（Findings）保持可见。已记录的审查仅完成所执行的审查任务。原任务
保持 review 状态，可以由个人接受或退回修正。个人批准不会被此审查替代。

时效性与限制
------
读取视图仅在重新比较当前的完整 Git/结果修订版本后，才确认已记录的审查。委托、
结果、路由、模型映射、策略或工作副本的更改会阻止未经检查的重复使用。审查任务
不会生成进一步的审查任务。读取调用不会创建表，也不会启动任何模型。

此组件将第二次模型调用与可追溯的审查证明连接起来。包括所有用户、GitHub、契
约和修正规则在内的完整自动完成决策，仍然是一个独立的待完成集成步骤。仅凭源码
更改不会激活原生安装。
