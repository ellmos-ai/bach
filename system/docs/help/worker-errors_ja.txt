ワーカーエラーとプロバイダ制限
===============

Ollama エラーは追加で backend_error として保存され、認証済みワーカーステータス
API 経由で射影されます。契約には検証済みフィールドのみが含まれます: provider、
kind、status_code (実際に存在する場合)、quota_exceeded、quota_period=month
(月間制限が明示的に報告された場合)、retry_after_seconds (有効な Retry-After ヘッ
ダが存在する場合)、および固定テキストから生成された message。プロバイダボディ、
URL、キー、その他のヘッダはこの契約に含まれません。エラーボディは最大 16 KiB
まで評価されます。読み取りは残りの総予算 BACH_LLM_TOTAL_CAP および既存の読み取
りタイムアウトも遵守します。読み取り不能、配信が遅すぎる、またはより大きなボ
ディはクォータ推測を提供せず、実際に受信した HTTP ステータスが保持されます。シス
テムスロットスナップショットにも正規化されたエラーフィールドのみが含まれます。

HTTP 429 だけでは月間制限の証明になりません。具体的な月間制限通知がない場合は
リクエスト制限が表示されます。Retry-After は非負の整数秒またはタイムゾーン付き
の HTTP 日付を受け付け、日付は現在時刻に対する相対値として評価されます。無効ま
たは欠落したヘッダは待機時間を生成しません。Retry-After は月間クォータのリセッ
トに関する約束ではありません。

FailedAnswer はチャット履歴の保存および再読み込み時にも検証済み契約を保持しま
す。このメタデータはモデルに返送されません。重大なプロバイダエラーの場合、ワー
カーは終了し、現在のタスクリースを確認付きで返却し、エラーテキストを保持します。
相関する assignment_ended イベントは履歴に個別に保持され、エラー原因を上書きし
ません。確認済みの新しい起動は前世代のエラーを削除します。

すでに明示的に起動された継続的な Ollama-Cloud ワーカーは、一過性の HTTP 429 の
後に同じ実行内で再開できます。ただし、現在のタスクリースに対してまだツールが起
動されていないことが証明されている場合に限ります。この証明は複数のモデルブロッ
クをまたぐ場合や CLI ブリッジ経由のツールにも適用されます。すでに開始されたツー
ル作業、または欠落もしくは無効な証明は自動再開を抑制します。確認済みの検疫 ACK
の後、タスクはレビュー用にネイティブステータス blocked でロックされ、そのリース
は解放されます。エラー表示は保持されます。別のワーカーはこの確認済み検疫を自動
で新たに引き受けることはできません。検疫 ACK が欠落しているか無効な場合、リトラ
イは抑制されたままとなり、実際のタスクステータスとリースは正規のタスク API 経
由で確認する必要があります。欠落した ACK はコミットの前または後に発生する可能性
があるため、blocked も解放も証明しません。ワーカーは Return-to-pending にフォール
バックしません。再度の解放の前に、すでに発生したツール効果を確認する必要があり
ます。リトライルールはべき等なツール作業を保証しません。
待機フェーズの前に Lease-Renew スレッドが終了され、タスクが確認付きで返却され、
Assignment が閉じられます。確認付きの返却がなければ待機も再作業も行われません。
待機中、ワーカーはアクティブですがタスクを処理しません: worker_active=true,
running=false, active_task_id=null。

ローカル再開ルールでは、合計最大 900 秒の計画待機時間で最大 3 回の連続再開が許
可されます。より長い有効な Retry-After がない場合、待機時間は 60、120、240 秒
です。実際に存在するより長い Retry-After は遵守され、残りの待機予算を超える場
合はワーカーが終了します。これらの値はプログラムルールであり、観測されたクォー
タリセット時間ではありません。バックエンドの成功応答のみがカウンタをリセットし、
古いエラー表示を削除します。月間制限、認証エラー、未知のエラー、および単発実行
はリトライされません。

停止、無効化、一時停止、有効期限、および世代交代は待機を中断します。その後、ス
ロット、モデル、タスクバージョン、依存関係、他者のリース、および Creator 猶予期
間が再チェックされます。この再開によって新しい起動承認、モデル変更、またはクラ
ウド自動起動は行われません。

既存の共有 GUI カードは current_activity を表示します。そのため、読み取り可能な
エラーテキストは backend_error をまだ評価しない GUI バージョンでも利用できます。
保存済み契約のない古いエラーが後から月間制限として出力されることはありません。ク
ラウド自動起動、無制限のリトライ、または有料のモデル変更はありません。クラウド
ワーカーはユーザーが起動します。


ワーカースロットの古い全体バージョンピンに対して、事前チェックは HTTP 409 および
error_code=configuration_version_conflict で起動を拒否します。応答には
admission.admitted=false が含まれ、世代やスレッドは作成されません。現在の
system-slots 設定状態を再読み込みし、明示的に新しい起動リクエストを送信してくだ
さい。その他の検証不能なスロットまたはアドミッションエラーは HTTP 503 および
error_code=worker_slot_unavailable のままです。


OpenRouter/Hermes トランスポートエラー
-------------------------------
既存の契約は provider=openrouter および provider=hermes も受け入れます。
OpenRouter は実際に設定されたホスト openrouter.ai に対してのみ指定され、その他
の OpenAI 互換 Hermes 宛先はアダプタ識別子 hermes を受け取ります。error_type
は固定の HTTPX クラスファミリに由来します: ConnectTimeout, ReadTimeout,
WriteTimeout, PoolTimeout, TimeoutException, ConnectError, RequestError または
HTTPStatusError。その他の RequestError サブクラスは一般的な RequestError ファ
ミリとしてのみ分類され、任意のクラス名は採用されません。そのため、空の例外テキ
ストでも安全なエラークラスが失われません。HTTP ステータスは実際に存在する HTTP
エラー応答からのみ採用されます。例外テキスト、URL、生ボディ、キー、ヘッダは表
示も記録もされません。この目的で HTTP ボディは読み取られません。ここでの
quota_exceeded=false はクォータ分類がないことを意味し、空きクォータの証明では
ありません。

RuntimeError 互換のキャリアは例外のままです。FailedAnswer はそのメタデータを再
正規化し、保存済みチャット、スロットステータス、GUI は同じ契約を使用します。
Assignment 終了後も安全な原因は保持されます。改ざんされたメタデータは検証済みの
原因を提供せず、任意の例外テキストを採用しません。

Hermes トランスポート試行は、変更されないタイムアウトと既存の待機時間で 4 回に
制限されたままです。このメタデータは追加のモデルフォールバックも Ollama-Cloud
再開も許可しません。モデル、無料価格バインディング、ツール検疫、リースおよび結
果ゲートは変更されません。すでに開始された、または未知のツール効果は自動的にリ
トライされません。

過去の試行 #2169 については実際のトランスポートエラークラスが証明されていませ
ん。新しい契約は今後実際に捕捉された例外のみを分類し、古いエラーに
ConnectTimeout もプロバイダクォータも帰属させません。


OpenRouter 無料カタログチェック
----------------------
具体的な OpenRouter 無料バリアントを選択する前に、ワーカーは現在のモデルカタロ
グを確認します。カタログキャッシュは 300 秒間有効です。カタログ GET は最大 2
回行われます: 単一のリトライはネットワークエラー、タイムアウト、または HTTP 408,
425, 429, 500, 502, 503, 504 の場合にのみ許可されます。HTTPX 呼び出しごとに 6
秒のリクエストタイムアウトが設定されており、これは両方の呼び出しに対する保証され
た合計時間制限ではありません。認証エラー 401/403 およびその他の HTTP エラーは
再リクエストされません。このカタログルールは推論呼び出しもツール効果も繰り返しませ
ん。

具体的な `:free` バリアントは、明確にリストされており、公開されているすべての価
格フィールドが存在し、有限であり、数値的にゼロである場合にのみ許可されます。欠
落、無効、またはゼロ以外の価格、およびリストされていないか曖昧なモデルは、別々
の選択原因を保持します: `model_price_missing`、`model_price_invalid`、
`model_price_nonzero`、`model_not_listed`、および `model_ambiguous` は別々のモ
デル理由であり、`model_not_free_variant` も同様に独立したままです。カタログエ
ラーは `catalog_timeout`、`catalog_transport_error`、`catalog_http_transient`、
`catalog_http_error`、`catalog_auth_rejected`、`catalog_invalid_schema` などの
コードを保持します。カタログエラーの場合、固定のエラーコードと安全なステータス
情報のみが出力され、プロバイダテキスト、URL、ボディ、キー、ヘッダは採用されませ
ん。
