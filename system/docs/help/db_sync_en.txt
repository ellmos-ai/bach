HANDLER NAME
============
db_sync - ProSync: Multi-System DB Synchronization


DESCRIPTION
============
ProSync synchronizes BACH databases between multiple systems.

Architecture:
- Each system has a local DB (~/.bach/bach.db)
- OneDrive serves as a transit hub (.SYNC/bach_db_transit/)
- Sync at BACH start (pull) and exit (push)
- 137 tables are dynamically recognized and synchronized

Smart Merge: Tables with timestamp columns use last write wins
with conflict check via heartbeat (5-minute window). Schema drift-proof
through shared columns detection and named INSERT. Secrets are created from backups
removed. Automatic cleanup strategy: Keep latest backups per host
plus everything under X days (default: 7 days, 10 per host).

Fail-soft behavior for OneDrive issues: transit backups are staged locally before
merge. If a specific pull candidate fails because of a cloud timeout or `disk I/O`
error, ProSync records that backup name in `~/.bach/sync_state.json` for about
30 minutes and skips it temporarily during startup syncs instead of blocking every
CLI call again.

ProSync is optional. Single-system installations do not require sync.
Configuration: bach setup prosync --multi-system / --single-system.


OPERATIONS
===========
bach db backup
  Created manual backup of bach.db.
  Format: bach_HOSTNAME_TIMESTAMP.bachdb (Example: bach_LAPTOP_2026-03-04T14-30-00.bachdb)
  Traeger: Local, not a remote request.

bach db sync
  Performs full sync: Pull (newer backups) + Merge + Push (own backup).
  Conflict check: If other PCs are active (heartbeat < 5min), confirmation is asked.
  Flags: --auto or -y for non-interactive mode.
  Merge strategy: Newer lines (timestamp) gain (INSERT OR REPLACE).
  Cloud-timeout candidates are deferred temporarily instead of retried on every startup.

bach db status
  Shows status: Local DB, backup folder, last 10 backups (host, time, size),
  active PCs and their heartbeat.

bach db cleanup
  Deletes old backups based on retention policy.
  Rule: Keep newest 10 per host OR anything younger than 7 days (configurable).
  Returns number of deleted backups.

bach db enable
  Enables auto-sync on startup/exit (sets configuration flag).

bach db disable
  Disables auto-sync.


EXAMPLES
=========
# Manual backup before risky operation
bach db backup

# Sync with conflict check (interactive)
bach db sync

# Unattended sync (cron job/automation)
bach db sync --auto

# Check status before sync (shows active PCs and backups)
bach db status

# Manually trigger cleanup of outdated backups
bach db cleanup


FILES
=======
Relative to system/:

hub/db_sync.py
  Core implementation (DBSyncManager, DBSyncHandler).
  Dynamic table recognition: 137 syncable tables (instead of hardcoded).
  Schema drift-safe through shared-columns + named INSERT.

~/.bach/bach.db
  Local production database (primary DB since ProSync).

data/bach.db
  OneDrive fallback DB (no longer described directly when ProSync is active).

OneDrive/.SYNC/bach_db_transit/
  Transit hub for .bachdb files and heartbeat.json.
  Heartbeat: Tracks active PCs (hostname, PID, timestamp) for conflict detection.

data/config/db_sync_enabled
  Flag for ProSync activation (created by "bach setup prosync --multi-system").

EXPLICIT LOCAL SHARED API (T903, 2026-09-30)
=========================================
The source seam hub/db_sync_adapter.py reuses unchanged, hash-bound adapter
code from Ocean 7127a0f5 and TransitSync 7648a20. It does not activate an Ocean
product runtime or startup/exit sync. No ambient tools import or installed-module
fallback is used.

SharedDBSyncConfig requires explicit absolute database/transit/state/marker/
heartbeat paths, node_id, namespace="bach", required_schema and user_version.
SharedDBSyncAdapter also requires ocean_root, carrier_root and a timezone-aware
clock. The caller owns application schema, database creation, an exclusive writer
claim and a quiescent database. Links/reparse paths and SQLite sidecars are
refused. The seam does not enforce global writer exclusion or locks.

API: adapter.handle(operation, dry_run=True, scope=None) returns the shared
OperationResult (supported/dry-run/refused/error, code, message, data).
Source/configuration failures may raise a refusal before this call.
Handler: DBSyncHandler.handle(..., shared_adapter=adapter, dry_run=...) selects
the seam BEFORE constructing the native manager. Without the explicit selector,
native dispatch remains; shared refusal never falls back to native writes.
The existing handler default dry_run=False is APPLY; the adapter default True
is preview. Callers must account for this difference.

Operation | Shared contract | Native classification / outstanding correction
backup    | Carrier snapshot, secret validation, heartbeat after publication
          | replaces only the selected call; native .bachdb backup stays separate
status    | verified snapshot metadata, marker, heartbeat, no changes
          | structured result replaces the unverified legacy inventory
enable    | atomically write exactly "enabled" at the injected marker
disable   | remove only this owned marker; refuse foreign content
          | native config paths stay unchanged; no activation is performed
cleanup   | explicitly selected local-node/all-nodes scope, UTC carrier retention
          | handler args --local-node/--all-nodes; never infer scope from a default
          | differs from legacy: manifest time replaces file mtime, explicit errors
init      | validate the existing explicitly declared schema and version
          | no first-copy, migration or inferred freshness

Push/pull/sync, aliases and unknown arguments are refused under this selector.
The native schema-0 database is NOT restamped: version 0 is invalid for this
unchanged shared API. A successful synthetic version-1 test does not authorize
changing native schema. Task1168 (stale first-copy in native init) and its actual
application-schema authority remain open.

Dry-run publishes/deletes/changes no files or directories. Status is read-only.
Snapshot publication followed by heartbeat failure returns
error/snapshot-published-heartbeat-failed with the snapshot evidence, not a false
rollback. Other carrier failures may leave partial effects and report
carrier-call-failed-state-unknown. Calls are synchronous: no bounded IO deadline,
cancellation or retry is promised. Carrier clock and retention stay unchanged;
the injected clock timestamps the heartbeat only.

Corrections (dry-run, credential/sidecar refusal, marker ownership, verified
status, selected cleanup scope and no first-copy) are explicitly classified,
not counted as native equivalence. The tested return path only removes the
explicit selector and retains shared artifacts; it does not prove migration or
restoration of legacy state.

Boundary: local API seam, no permanent packaging/runtime dependency, BACH-IN/P8,
three-way parity, migration/rollback or off-host acceptance. The parity register
remains push/pull/sync = 3/9. Deployment and schema-0/Task1168 requirements must
be resolved separately before actual calls are switched over.
