================================================================================
subscription_agents - Versioned onboarding prompt preview
================================================================================

DESCRIPTION
--------------------------------------------------------------------------------
The `subscription_agents` handler generates a versioned onboarding prompt preview
from the current BACH sources (subscription-agents compose). To do this, the
handler reads a request file in JSON format, passes the content to the composer
(`hub/_services/subscription_agents_composer.py`) and outputs the result as
 canonically sorted JSON to stdout.

The handler is read-only with respect to the request file: it modifies neither
the request file nor configuration or system files. The output is suitable as a
basis for versioned prompt/onboarding states and for passing on to downstream
tools.

The handler provides exactly one operation: `compose`.

Registration name:       subscription_agents
Module:                  system/hub/subscription_agents.py
Associated service:     system/hub/_services/subscription_agents_composer.py
Operation(s):            compose

OPERATIONS
--------------------------------------------------------------------------------
compose <request-json-file>
    Creates a versioned onboarding prompt preview from the current BACH
    sources.

    Arguments:
      <request-json-file>    Path to a JSON file containing a JSON object.
                             A leading `~` is expanded to the home directory
                             of the executing user.

    Rules for argument passing:
      - Exactly one argument is required.
      - The argument must be a non-empty string.
      - The argument must not start with `-` (no option parsing).

    Error handling for the request file:
      - File not readable (OSError/PermissionError)
        -> "Request file is not readable"
      - File larger than MAX_REQUEST_BYTES (256 KB)
        -> "Request file exceeds 256 KB"
      - Content is not valid UTF-8 JSON, not a JSON object, or contains
        duplicate field names
        -> "Request file must contain valid UTF-8 JSON with unique fields"
        -> "Request file must contain a JSON object"

    If the operation or argument is not accepted, the handler returns the
    following usage line:

      bach subscription_agents compose <request-json-file>

EXAMPLES
--------------------------------------------------------------------------------
1) Standard call using the handler's short name:

     python bach.py subscription_agents compose ./request.json

2) Call using the option form (binding to the handler):

     python bach.py --subscription_agents compose ./request.json

3) Request file in the home directory (tilde expansion):

     python bach.py subscription_agents compose ~/requests/onboarding.json

4) Redirect output to a file (sorting/keys are preserved):

     python bach.py subscription_agents compose ./request.json > preview.json

5) Minimal request file (JSON object, UTF-8, no duplicate fields):

     {"topic": "onboarding", "audience": "new_agent"}

OUTPUT FORMAT
--------------------------------------------------------------------------------
- Success case: exactly one JSON object on stdout, serialized with
  `json.dumps(result, ensure_ascii=False, sort_keys=True)`. Keys are sorted
  alphabetically, non-ASCII characters remain unmasked (UTF-8).
- Error case: return of a text (error message or usage line) via the regular
  handler return; exit status depends on the calling CLI.
- The output contains no trailing newline added by the handler itself.
