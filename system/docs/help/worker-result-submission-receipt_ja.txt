ワーカー結果提出の証明
===========

#2210 のこのコンポーネントは既存の結果サービスを補完します。どのタスクバージョ
ン、ワーカー世代、およびフェンスの下でどの結果が提出され、その際にどのワーカー
ポリシーが保存されていたかを記録します。タスク、結果、および修正の管理は従来の
BACH ストアに留まります。

証明の内容
-----

リースサービスは書き込みトランザクションの下で有効な作業リースを確認します。結
果、review へのステータス変更、リースの解放、および履歴証明は同じトランザクショ
ンに属します。後の証明には引き続きアクティブな Claim-ID は不要です: リースは提
出時に意図的に返却されました。より高いフェンス、変更された依頼、または新しい修
正ラウンドは古い現在の結果状態を無効にします。

証明はタスクと結果を世代、フェンス、タスクバージョン、結果ダイジェスト、過去の保
持者名、提出時刻、ステータスイベント、および解放イベントと結び付けます。保持者
名はリースリクエストに由来します。モデルアイデンティティを確認せず、レビュアー権
限も付与しません。

提出時点で利用可能なグローバルポリシーとタスクオーバーライドは、設定バージョン
とともに記録されます。後の設定変更がこの過去の構成を書き換えることはありません。
オプションの共通ポリシー契約または構成ストアが欠落している場合、これは証明内で
利用不可として明示的に認識可能なままになります。結果の提出は引き続き可能です。

タスク完了との境界
---------

提出証明は保存された提出とその履歴を確認します。技術的な完了には、スコープとプ
ロジェクト状態、ワークツリーフィンガープリント、現在のロック、契約履行、認証済
み独立モデルレビュー、および該当する場合は GitHub 受け入れのための個別ソース
が引き続き不足しています。PR アドレスだけでは現在の Head、合格したチェック、ま
たは承認を証明しません。

保存されたポリシーはまだ適用されたポリシー決定ではありません。このコンポーネン
トは自動的な done を生成せず、必須のユーザー受け入れも代替しません。既存の提出
ペイロードには引き続き generation と result のみが含まれ、ワーカーは独自の整合
性フラグを設定できません。確認された解放は accepted=false で review のままです。

互換性と運用
------

古い結果行は Legacy として読み取り可能です。新しい提出には独自のバージョン識別
子が付与され、証明フィールドの欠落によって古いデータになることはありません。後
から捏造された完全な提出証明を受け取ることはありません。新しい証明は正規の結果
行および関連する履歴イベントに対して検証されます。破損した、または誤って割り当
てられた証明は、現在の結果受け入れを許可してはなりません。

スキーマ拡張は、提出および修正用の既存の明示的なスキーマ書き込みパスで行われま
す。結果 GET はスキーマもデータも変更しません。本番のインストールまたはマイグ
レーションはこのドキュメントによって実行も承認もされません。

リードバックとさらなる統合
-------------

GET /api/tasks/{id}/result は result.submission の下で提出証明の可用性を返しま
す: available、unavailable、または legacy_release_only。ハッシュ
submission_revision は過去の提出証明をバインドします。これは共通の完了契約のた
めの完全な result_revision ではなく、前述のスコープ、プロジェクト、および作業
状態の証明が不足しています。

凍結されたポリシーの可用性は result.submission.policy.availability の下に別個
に示されます。利用不可のオプションポリシーメタデータは、このコンポーネントにお
いて有効な提出も従来の個人受け入れおよび修正経路もブロックしません。一方、破損
した提出証明は受け入れをブロックします。さらなる自動完了動作に関するポリシー決
定はまだここに保存も実行もされていません。
